# 合併後文件流程檢查

盤點基準：095629b3f670202ea8e5149db65b03ee8a0076b3。此為文件與流程檢查，不是真實使用者測試，也不代表應用程式測試或 runtime 驗證通過。

## 檢查方式與發現

逐項對照當時的 WORKFLOW、USAGE、AGENTS、PRD、AC、測試與 review 文件；另掃描 Markdown 中非程式碼、非註解的相對檔案連結。範例中的假路徑不當作實際工件，未檢查外部連結與所有標題 anchor。

| 路徑 | 檢查結果 |
|---|---|
| 使用者只描述困擾 | 可由釐清流程開始，未知不要求填成承諾 |
| 使用者沒有數字門檻 | 可先基準量測或明確人工判準 |
| 暫無產品 AC | 可做已有授權、範圍與完成條件的探索 |
| 正式實作 | 依本輪已確認 AC；不將草案視為同意 |
| 實驗結果與審閱狀態 | 發現範本同時寫開始／結束進 in-review，已統一為執行完待審 |
| prompt 與探索 | 明確生產契約不阻擋探索 prompt；同步重大 schema 變更規則 |
| 追溯 | 修正新增 AC 欄後的 ADR 欄位說明 |
| review 與交付 | 保留版本證據、合併與部署／結案分開 |
