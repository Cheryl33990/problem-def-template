# 真實案例試跑

## 目標

驗證模板能否協助找到下一步、改進決策並降低接手成本。填寫完整度與問題解決效果分開記錄。

## 執行

1. 選一個已有結果的熟悉案例回放，只用當時已知資料，標註事後才知道的資訊。
2. 選一個正在進行的案例，先記需求與未知數，確認範圍後只做一項高風險驗證。
3. 一週後由自己或另一位讀者，只靠案例文件說出目標、證據、決策與下一步。
4. 按實際卡點修模板；不要因為單次不順就新增大量欄位。

| 項目 | 回放案例 | 進行中案例：ipas-learning-hub |
|---|---|---|
| 資料來源、日期、版本 | 待選 | ipas-learning-hub `5891f4c`，2026-11-16～18，21 個 PR；見[案例研究](../about/case-study-ipas.md) |
| 首次寫出有證據的下一步所需時間 | 待測 | 未計時；第一天（11-16）即完成探索一、二並據此決定原型範圍 |
| 文件維護時間／實際分析時間 | 待測 | 未計時；progress 膨脹到約 196 KB，顯示維護成本偏高 |
| 因證據修改的假設或決策 | 待測 | 有：v1 5/8 → 未命中診斷 → 評估 v2；探索一改由 AI 代填，影響 A／B 分類意義 |
| 一週後接手所需時間與誤解 | 待測 | 未測 |
| 無用欄位、重複填寫、跳過理由 | 待測 | PRD、approach、ADR、experiments、testing、closure、meta 未獨立建檔，內容寫在 brief |
| 問題結果與未解風險 | 待測 | 保留題 243 題混合 87.2%；單一模型與領域、判讀者為作者本人 |

依進行中案例的結果，已在模板加入 progress 輪替規則（只留目前狀態，舊紀錄移到 docs/project/log）。

## 試跑前確認的候選門檻

下列為建議，需由使用者確認再作為驗收：30 分鐘內找出第一個可執行驗證；一週後 10 分鐘內接手並正確指出關鍵未知數；每個決策能追到證據或明確假設。沒有決策改變也可接受，但須說明證據為何支持原方向。

未達標就記原因與下一輪調整，不宣稱模板已有效。合成示例不能取代上述兩個真實案例。
