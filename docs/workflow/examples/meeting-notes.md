# 合成示例：會議待辦漏追蹤

> 全部人物、數字與結果均為教學用合成資料，未執行真實使用者測試。採精簡流程，把欄位合併在本檔。

## 問題、範圍與成功指標

使用者：一位每週主持五場會議的專案負責人。症狀：會後待辦常漏掉。假設原因：會議紀錄缺負責人與期限；尚不能排除真正原因是工作量太大。
目標 M-01：讓會後待辦都有可追蹤的責任人與期限。
只做紀錄方式改善；不買軟體、不做程式。設計與 implementation 為 N/A；重大架構 ADR 為 N/A，選擇理由留在本檔。

## 證據與子問題

合成觀測 D-01：五份會議紀錄共 20 條待辦，其中 8 條缺負責人，10 條缺期限。取樣只含一週，不能推論全團隊。
子問題 Q-01：會議結束前能否補齊責任人？Q-02：期限能否當場確認？
「缺欄位導致漏做」仍是假設，填齊率並不等於任務完成率。

## 方案比較與決定 DEC-01

| 方案 | 成本 | 限制 |
|---|---|---|
| 維持現況 | 無額外時間 | 無法改善可追蹤性 |
| 會末兩分鐘確認待辦表 | 小量固定時間 | 依賴主持人執行 |
| 導入新任務工具 | 導入與學習成本 | 不保證有人填資料 |

暫選會末確認，因為可逆且不用購置工具；若耗時過多就回復原方式。

## AC-01 與實驗 EXP-001

AC-01 對應 M-01：下一輪五場會議至少 90% 的待辦含有效責任人與期限；每場增加時間不超過三分鐘。
規格：事前固定五場會議；會後逐條檢查，不把空白、未知或「大家」算責任人。記錄當場確認時間。
假設 H-01：會末確認能達到 AC-01。若不足 90% 或任一場超時則未通過；不為通過而事後改門檻。
基準：D-01；資料與工具：人工表格、計時器，無 AI prompt，故 prompt 欄為 N/A。

## 合成結果與分析

示例觀測：五場共 20 條待辦，19 條完整；增加時間為 2、2、3、2、2 分鐘。
AC-01：19／20＝95%，時間均不超過三分鐘，示例判定通過。
限制：沒有驗證任務實際完成率、長期使用與其他主持人。不能據此宣稱已解決漏做問題。

## 追溯、結案與接手

M-01 → AC-01 → D-01、H-01 → DEC-01 → EXP-001 → 上述逐項量測。
本輪只驗證記錄完整性，合成結果支持保留此方案；尚未驗證的漏做問題另列下一輪。
做得好：小型、可逆測試。待改善：樣本短，且代理指標可能誤導。
下一步：由負責人追蹤一週任務完成情形，再判斷是否真的減少漏做。
