# 驗收條件（Acceptance / Definition of Done）

> **範本庫文件**：需要時才複製到專案紀錄區。本檔連結供瀏覽範本；複製後須改為實際專案文件，未建立的依賴標待建立或連到 brief。做法見 [使用指南](../../guide.md)。

本文件把 `PRD.md` §4 的**成功指標**翻譯成**可驗證的二元條件**——
每條使用穩定 AC-NN 編號（刪除後不重用），並且都必須能被某種方式證明「達到 / 沒達到」，可使用事前定義、可重做的人工判準；避免無依據的主觀評語。

> 本檔回答「什麼樣才算做完？」；具體「怎麼測試？」交給 `docs/project/testing/`。

---

## 0. AC 形成與確認

AI 先把期待轉為可觀察的成功條件，再草擬本表。不要求使用者提供專業指標或自行填門檻。
未知數值先標未知並安排基準量測；AC 草稿維持暫定，不能用來宣稱產品通過。探索任務可先以疑問、授權範圍與完成條件執行，不必虛構產品 AC。
正式實作前確認本輪使用的 AC；以下逐項記錄（也涵蓋非功能性條件）：

| AC ID | 成熟度 | 判準依據／尚缺資訊 | 確認人與日期／後續探索 |
|---|---|---|---|
| AC-01 | 未知 | 待提出 | 待釐清 |

成熟度用未知／暫定／已確認，不代替文件 status 或當次測試結果。確認是採用目標，不代表已達成；修訂保留原因與原結果。

## 1. 原則

- **二元判定**：已確認的每條驗收條件都要有明確 yes/no 判定，不能寫「盡量」「應該」這類軟詞
- **可量測**：若是數值指標，要寫明量測方式、樣本量、計算公式
- **可追溯**：每條都要對應到 PRD §4 的某條成功指標（用編號）
- **可驗證時機**：寫明何時驗收（每次 commit / 釋出前 / 試運行階段）

## 4. 結案閘門（Closure Gate）

先完成下列驗收，再進入 `docs/project/closure/` 執行完成清單與復盤。驗收通過不等於已結案。

- [ ] PRD.md `status: approved`
- [ ] 所有成功指標都在本表有對應驗收條件
- [ ] 驗收條件都有 `docs/project/testing/acceptance_tests/` 內的對應測試
- [ ] 所有對應測試通過
- [ ] 非功能性條件全數達標
- [ ] `docs/project/meta/traceability.md` 已更新並對齊
