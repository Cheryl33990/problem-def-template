# 測試策略範本 

> **範本庫文件**：需要時才複製到專案紀錄區。本檔連結供瀏覽範本；複製後須改為實際專案文件，未建立的依賴標待建立或連到 brief。做法見 [使用指南](../../guide.md)。

> 衍生時改 draft，填入實際專案工具與指令。本模板未安裝測試框架或 CI。

## 3．規格與結果
每條 AC 使用 [acceptance_tests/TEMPLATE.md](acceptance_tests/TEMPLATE.md) 建規格。執行後用 [validation/TEMPLATE.md](validation/TEMPLATE.md) 保存被測版本、步驟、結果與限制。
程式測試放實際 tests 目錄；規格與結果目錄只放文件。精簡模式可合併，但仍須分清預期與觀測。

## 4．失敗處理
Draft 分支可保留失敗結果供診斷；不得把失敗或 skip 宣稱通過。正式交付必要 AC 未達標就回到實作或需求確認。
flaky 測試記重現條件與 issue，不靠重跑一次綠燈掩蓋；暫時停用須附原因、風險、負責人與恢復計畫。
變更後重跑受影響項目；擴大驗證以未解風險為依據。修門檻先取得確認並保留原結果。
